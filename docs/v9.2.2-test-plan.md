## 5. Rollback

- **Frontend or API:** see "Rollback" in `docs/promotion-checklist.md`. The new cache format is backward-compatible in one direction only: v9.2.2 reads old rows, but **v9.2.1 can't read generation-keyed rows**. After a rollback, re-run the scraper once so it writes legacy-format rows:

  ```bash
  aws lambda invoke --function-name cartwise-scraper --payload '{"source":"admin"}' out.json
  ```

  This is a manual run, so no emails are sent.

- **Recovering a skipped store after a Publix outage:** re-run the scraper with emails on:

  ```bash
  aws lambda invoke --function-name cartwise-scraper \
    --cli-binary-format raw-in-base64-out --payload '{"source":"aws.events"}' out.json
  ```

  ⚠ This emails **every** user, including stores that already got this week's email. To avoid duplicates, use Admin → resend for the affected users instead.
