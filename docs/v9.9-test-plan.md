# CartWise v9.9 — Test Plan (feedback, verify on Notifications)

**Flow:** one-time SSM setup → automated tests → staging deploy → manual checks → Ben approves → production deploy.

## What changed

| Area | Change |
|---|---|
| Feedback | 💬 **Feedback** in the sidebar and phone menu opens a form: Bug / Idea / Question / Other and a message (2,000-character limit with counter). |
| Who can send | Signed-in, **verified** accounts only. Unverified users see "Please verify your email first" with a button to Notifications. |
| Limits | 5 messages an hour and 20 a day per account. |
| Storage | New table `cartwise-feedback` (and `cartwise-staging-feedback`), kept 1 year. Saved before any email is sent. |
| Notification | Emailed to the address in SSM `/publix/feedback-to`. Reply-to is the sender's verified sign-in email (taken from the session, never from the form). The message is escaped; the subject is one line. Staging emails say "[Cartwise staging feedback]". |
| Context | Page, app version, store and a short browser description are attached. No cookies or tokens. |
| Admin | **Admin → Feedback**: newest first, "Show done", ✉️ Reply (opens your mail app), ✓ Mark done / ↺ Reopen, red count of new messages in the sidebar. |
| Verify email | Notifications shows a "Verify your email to get alerts" card for unverified accounts: **Send verification email** and **I've verified, check again**. The top banner stays. |
| Fix | After a page reload the verify banner disappeared, because restored sessions were assumed verified. `/user/prefs` now returns `email_verified`, and the existing focus / 5-minute session check refreshes it, so verifying in another tab clears the banner and card when you come back. |

## 0. One-time setup (SSM, shared by staging and production)

```bash
aws ssm put-parameter --name /publix/feedback-to --type String --value 'YOUR_ADMIN_ADDRESS'
```

Without it, feedback is still saved and shown in Admin, just not emailed (the deploy prints a note).

## 3. Manual checks on staging (hard-reload)

**T1 · Send.** Signed in as a verified user, click 💬 Feedback, pick Idea, type a message, Send. **Pass:** "Thanks, we got it"; an email arrives at the admin address titled "[Cartwise staging feedback] Idea from …"; pressing Reply in Gmail addresses the user.

**T2 · Validation.** Send with no type, then with an empty message. **Pass:** inline errors, nothing sent. The counter turns amber near 2,000 and stops at 2,000.

**T3 · Escaping.** Send `<b>bold</b> <script>alert(1)</script>`. **Pass:** the email and Admin show the text literally; nothing bold, no alert.

**T4 · Rate limit.** Send 6 quick messages. **Pass:** the 6th says "You've sent several messages recently".

**T5 · Admin.** Admin → Feedback. **Pass:** messages newest first with page / store / app / browser; red count in the sidebar; ✓ Mark done hides it (Show done brings it back, faded); ↺ Reopen restores it; ✉️ Reply opens a new email to the user.

**T6 · Unverified.** Sign in with an unverified test account.
- **Pass:** the top banner shows, **and still shows after a page reload** (that was the bug).
- Notifications shows the yellow "Verify your email to get alerts" card. **Send verification email** says it was sent.
- Open the link in another tab, come back, click **I've verified, check again** (or just switch back to the tab). **Pass:** the card and banner disappear.
- 💬 Feedback for an unverified account shows "Please verify your email first" and **Go to Notifications**.

**T7 · Regression.** Deals, My List autocomplete, Admin → Users sorting, Send Test Email.
