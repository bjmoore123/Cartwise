# CartWise v9.11 — Test Plan (Forgot PIN, verification reminders)

**Flow:** automated tests → staging deploy → manual checks → Ben approves → production deploy.

## What changed

**Forgot PIN (sign-in page)**

| Step | Behavior |
|---|---|
| "Forgot PIN?" | Under Sign In. Opens "Reset your PIN" with the email already filled in if you typed one. |
| Request | Always answers "If an account exists for that email, we've sent a link… expires in 30 minutes", whether or not the account exists, and takes at least 1.5 s either way. 3 requests an hour per email, 10 per IP; extra requests get the same answer and no email. |
| Email | "Reset your Cartwise PIN" with a button. The link works once, for 30 minutes; requesting again replaces it. |
| Link | Opens "Choose a new PIN". The token is removed from the address bar immediately and the link is checked first: a good link shows the PIN boxes and "This link expires in N minutes"; a dead one shows the error and **Request a new link** without asking for a PIN. Leaving the page open past the expiry switches it to the error. |
| Save | New PIN set, lockout cleared, all devices signed out, email marked verified, "Your Cartwise PIN was changed" notice sent. Back to Sign In with the email filled in. |
| Bad link | Used, expired, edited or wrong-account links all say "This reset link is invalid or has expired" with **Request a new link**. |

**Verification reminders**

| Rule | Value |
|---|---|
| Who | Accounts with `email_verified = false` (not legacy accounts without the flag) |
| When | 7, 14, 21, 28 days after sign-up; checked daily at 15:00 UTC (10 AM EST / 11 AM EDT) |
| How many | 4, then stop. Never two within 6 days. Verifying stops them. |
| Link | Fresh each time, valid 7 days (the sign-up link only lasts 48 hours) |
| Logs | Each email in Admin → Logging (email), plus a daily "Verification reminders: N sent" entry |

**Unsubscribe link in every email**

Every email to a user ends with "Unsubscribe from Cartwise emails" (verification, PIN reset, PIN changed, test email, reminders, weekly alert), and mail apps show their own Unsubscribe button. The link needs no sign-in and works for unverified accounts. It stops weekly alerts and reminders; emails the person asks for (PIN reset, resend verification, test email) and the PIN-changed notice still arrive.

**Branded emails**

Every email and the pages their links open use the brand layout: green header with the Cartwise logo, cream background, serif headings, green buttons. Deal rows in the weekly email stack the name, price and savings so nothing gets squeezed on a phone.

The monthly cleanup still deletes 30-day-old accounts with no store or no items; reminders 1–4 all go out before that.

## 3. Manual checks on staging (hard-reload)

**T1 · Request, real account.** Sign-in → Forgot PIN? → your staging email → Email me a reset link. **Pass:** the generic message; the email arrives within a minute.

**T2 · Request, no account.** Use `nobody-12345@example.com`. **Pass:** exactly the same message, and nothing in Admin suggests an account.

**T3 · Reset.** Open the link. **Pass:** "Choose a new PIN for …" with "This link expires in 30 minutes" (or a bit less); the address bar shows no token. Enter two different PINs → "don't match". Enter `1234` twice → "too common" (the link still works). Enter a good PIN twice → back on Sign In, email filled in. Sign in with the new PIN. The "PIN was changed" email arrives. Another browser that was signed in gets signed out.

**T4 · Link used twice.** Open the same email link again → straight away (no PIN boxes) "invalid or has expired" and **Request a new link**. Same for an older link after requesting a newer one.

**T5 · Rate limit.** Request 4 times quickly for the same email. **Pass:** same message every time; only 3 emails arrive.

**T6 · Reminders (simulated).** Make a test account, don't verify it, then backdate it and run the job:

```bash
aws dynamodb update-item --table-name cartwise-staging-users --key '{"email":{"S":"YOUR_TEST_EMAIL"}}' \
  --update-expression "SET created_at = :c" --expression-attribute-values '{":c":{"S":"2026-11-01T00:00:00+00:00"}}'
aws lambda invoke --function-name cartwise-staging-scraper --cli-binary-format raw-in-base64-out \
  --payload '{"source":"verify-reminders"}' out.json && cat out.json
```

**Pass:** `{"sent": 1, …}`, the reminder email arrives, and its Verify button verifies the account. Run the invoke again → `"sent": 0` (6-day gap). Admin → Logging shows the email and the summary.

**T8 · Unsubscribe from an unverified account.** Use the T6 account (still unverified) and a reminder email it received. Scroll to the bottom → **Unsubscribe from Cartwise emails** → "Unsubscribe from Cartwise emails?" → Yes. **Pass:** "You won't get deal alerts or reminders…". Run the T6 invoke again after backdating `created_at` another week → `"sent": 0`. Opening the link again says "Already Unsubscribed".

**T9 · Footer on every email.** Check the bottom of the T1 reset email, the T3 "PIN changed" email, a Send Test Email from Notifications and a Resend Weekly Email: each has the unsubscribe link. In Gmail, the reminder and the weekly email show "Unsubscribe" next to the sender.

**Shortcut for T1, T3, T6, T8, T9 and T10:** `bash tools/test_emails.sh` sends one of every email to your inbox from a throwaway `moore.ben+cw…` staging account, pausing where you need to click, and checks the unsubscribe at the end.

**T10 · Email look.** Open each email from T1–T9 in Gmail on a computer **and** on your phone (and Outlook if you have it). **Pass:** the logo shows in the green header (if Gmail asks, click "Display images"); buttons are on one line; no sideways scrolling; your address isn't split mid-word; the weekly email's product names use the full width. Also check `https://<staging site>/email-logo.png` loads.

**T7 · Regression.** Normal sign-in, Create Account, Admin lock, the logo.

## 4. Rollback

Revert and redeploy. Reset links in flight stop working (harmless). To stop reminders without a redeploy: `aws events disable-rule --name cartwise-verify-reminders`.
