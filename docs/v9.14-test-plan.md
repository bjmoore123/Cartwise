# CartWise v9.14 / v9.14.2 — Test Plan (clickable reports, user groups, per-user history, Back button)

**Flow:** automated tests → staging deploy → checks → Ben approves → production deploy.

## What changed

| Area | Change |
|---|---|
| Reports | Numbers that are a group of people are links (underlined). Clicking one opens Admin → Users showing exactly those accounts. |
| Users | Group dropdown with counts, a "Showing N users" banner, an extra column for the group, and **⬇ CSV** for whatever is shown. |
| History | Click any email address in Users for that person's history: summary, what's missing, and every event by month, with filters. |
| Recording | From this release nothing per-person expires (except feedback, 1 year): days on the site, sign-in events, alerts off/on and how, and each email (3 years). |
| v9.14.2 | Almost every number that counts people is now a link: tiles, funnel, verification, sign-ins, list and location/item/month bars. Log counts open the right log, already filtered; Open feedback opens Feedback. Back/Forward move between admin views (tab, group, filter, scroll, history dialog), and a reload keeps the view. |
| One-time step | The deploy copies the 90-day sign-in log and 30-day email log onto each account and marks what history is missing (`history_gaps`). It runs every deploy and skips accounts already done. |

## 3. Checks on staging (hard-reload)

**T1 · Click through.** Reports → How people use Cartwise → click a number (e.g. Site only, 30 days). **Pass:** Users opens with the banner "Showing N users: Site only, last 30 days", N matches the number you clicked, and the dropdown shows the same group.

**T2 · Every link.** Try Alerts off in total, Unverified, reminders still going, a funnel drop-off (−N), Empty lists. **Pass:** each list's size equals the number clicked; Show all users clears it.

**T3 · Extra column and CSV.** Pick "Alerts turned off". **Pass:** a Turned off column with date and how. Click ⬇ CSV: a file named `cartwise-users-alerts_off-<date>.csv` with only those users.

**T4 · History.** Click your own email. **Pass:** summary tiles; an "Incomplete history" box listing what's missing for an older account; events by month (days on the site, emails with delivered/opened, sign-ins). Filters change the list. Close with ×.

**T5 · New recording.** Turn alerts off in Notifications, then on again. **Pass:** your history shows "Turned off weekly alerts · via settings" and "Turned weekly alerts back on · via settings". Enter a wrong PIN once, then sign in. **Pass:** "Wrong PIN entered" appears.

**T6 · More links (v9.14.2).** Click Total users, Verified, a funnel count, Verified within 24 hours, Signed in (7 days), a location bar, a popular item and a month bar. **Pass:** each opens Users with a banner naming that group or filter, and the list size matches. Click Failed sign-ins: Logging opens on the sign-in log filtered to failures. Click Open feedback: Feedback opens.

**T7 · Back button (v9.14.2).** Scroll halfway down Reports, click a number, then press the browser's Back. **Pass:** Reports again, at the same scroll position. Forward returns to the list. Open someone's history and press Back: the dialog closes and the list stays. Click Logging in the sidebar, then Back: the previous tab. Reload on a filtered list: the same list.

**T8 · Regression.** Sign in, deals, list, Notifications, Forgot PIN, Reports load, weekly report button.

## 4. Production

Same deploy. Confirm `Account history preserved` in the output, then repeat T1, T4 and T7.

## 5. Rollback

Revert and redeploy. The new account fields are harmless if left. The one-time step never deletes anything.
