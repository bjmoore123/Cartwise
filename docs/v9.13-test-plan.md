# CartWise v9.13 — Test Plan (how people use Cartwise, verification counts, attention fixes)

**Flow:** automated tests → staging deploy → checks → Ben approves → production deploy → backfill.

## What changed

| Area | Change |
|---|---|
| Engagement | A person counts as engaged if they **opened or clicked a weekly deal alert** or **used the site** (signed in, or visited with a saved session). Reports shows email and site / email only / site only / not seen, for 7 and 30 days. |
| Site use | Recorded on every signed-in visit (at most every 30 minutes), not just password sign-ins. |
| Email use | Each email is now linked to the account it was sent for, so an open is credited correctly even when alerts go to another address. |
| Admin → Users | New **Verify Emails** column (verification emails actually sent). **Last Active** replaces Last Login: the latest site use or alert open, with site / email chips for the last 30 days. |
| Needs attention | "Unverified after all reminders" only counts accounts that have had all 4 reminders and whose last link expired. The deal-fetch warning waits until the last run is more than 8 days old. |

**What starts empty:** daily charts and site/email counts build up from the deploy on. Email opens only count for weekly alerts opened after open tracking was turned on in Resend. The Verify Emails column shows "?" until the backfill runs.

## 3. Checks on staging (hard-reload)

**T1 · Site use.** Sign in to staging as a normal user (not admin), browse a couple of tabs. Then Admin → Users. **Pass:** that user's Last Active is today with a **site** chip.

**T2 · Saved session counts.** Close the tab, reopen the staging site (still signed in, no PIN). Wait 30+ minutes first if you want to see the time move. **Pass:** Last Active updates; no sign-in needed.

**T3 · Reports.** Admin → Reports. **Pass:** "How people use Cartwise" shows the split; "Engaged this week" tile; Verification shows "Unverified, reminders still going" and "Unverified after all 4 reminders" (0 for accounts that have only had their first reminder); no "28 days" message in Needs attention.

**T4 · Verification count backfill (dry run, read-only).**

```bash
python tools/backfill_verify_counts.py --env staging
```

**Pass:** a table of every staging account with sign-up/resend emails, reminders, total and last sent. Then `--apply`, refresh Admin → Users: the Verify Emails column shows numbers instead of "?".

**T5 · Live count.** In Admin → Users, click **Resend Verify** on an unverified test account. **Pass:** its Verify Emails number goes up by one.

## 4. Production

After the production deploy:

1. Run the backfill for production, dry run first and read the table:
   ```bash
   cd /c/Projects/Cartwise/production
   python tools/backfill_verify_counts.py --env prod
   python tools/backfill_verify_counts.py --env prod --apply
   ```
2. Admin → Users: check the Verify Emails column against the dry-run table.
3. After Wednesday's deal emails go out, open yours; within a minute or two your Last Active shows an **email** chip and Reports → "How people use Cartwise" counts it.

Revert and redeploy. The new fields on accounts and the day rows are harmless if left in place.
