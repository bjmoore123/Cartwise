# CartWise v9.5 — Test Plan (accounts and security)

**Flow:** automated tests → staging deploy → manual checks below → Ben approves → production deploy, combined with the secret rotation in section 4.

## What changed

| # | Fix | Where |
|---|---|---|
| 1 | A session whose account no longer exists is rejected. Before, it kept working for its full 30 days after the account was deleted or its email changed. | `helpers.get_session` |
| 2 | Deleting an account, an admin delete, or an admin email change signs out **every** session for that email, not just the current one. | `helpers.revoke_sessions`, `prefs.delete_account`, `admin.admin_delete_user`, `admin.admin_reset_email` |
| 3 | `UNSUB_SECRET` has no default. If it's missing, unsubscribe links are neither issued nor accepted. Before, the API fell back to `changeme-set-in-deploy`. | `helpers.py` |
| 4 | The verification link URL-encodes the email, so `ben+test@…` works, and the email's HTML is escaped. | `auth._send_verification_email` |
| 5 | Registering an email that already has an account no longer says "Account created!". The server answer is unchanged, so it still doesn't reveal which emails exist. | `app.js doAuth` |
| 6 | Signing out clears the previous user's cards, matches, banner and cached data from the page. | `app.js doLogout` |
| 7 | Admin "Last run" (scrape logs) and Inbound logs read the whole table and sort newest-first. Before, they used one arbitrary page. | `admin.py`, `helpers._scan_all` |
| 9 | Admin sessions record a fingerprint of `ADMIN_SECRET`. Rotating the secret ends every admin session made with the old one; before, they lasted their full 12 hours. Every existing admin session ends once at deploy. | `helpers.get_admin_auth`, `admin.admin_login` |
| 10 | Open tabs notice a revoked session. Any 401 from a user endpoint returns that tab to sign-in with "Your session has ended", and the session is re-checked when the tab regains focus (at most once a minute) and every 5 minutes. Before, a revoked tab kept showing the app until a full reload. `/deals` responses are now `private`, so they're never held in a shared cache. | `app.js` fetch wrapper, `sessionEnded()`, `deals.py` |
| 8 | "Users Deleted" now counts self-deleted accounts and monthly-cleanup deletions as well as admin deletes. | `helpers.count_deleted_user`, `scraper/main.py` |

## 3. Manual checks on staging

Use a throwaway staging account, for example `you+cw1@gmail.com`, so you don't delete your real one.

**T1 · Plus-address verification (#4)**
1. Register `you+cw1@gmail.com`.
2. Open the verification email.
3. **Pass:** the link contains `%2B`, and clicking it shows "Email verified".

**T2 · Delete signs out everywhere (#1, #2, #8)**
1. Sign in as the throwaway account in two browsers, for example Chrome and an Incognito window.
2. In one of them, go to Account → Delete account.
3. **Pass:** switch to the other browser. When its tab regains focus, or on its next save (for example, adding a list item), it returns to sign-in with "Your session has ended. Please sign in again." A tab left in the background notices within 5 minutes.
4. **Pass:** Admin → Overview "Users Deleted" went up by 1.

**T3 · Admin email change (#2)**
1. Register and verify a second throwaway account, then sign in with it in another browser.
2. In Admin → Users, change its email.
3. **Pass:** the other browser returns to sign-in when you switch to it, as in T2.
4. **Pass:** signing in with the **new** email and the same PIN works.

**T4 · Register an existing email (#5)**
1. On the Create Account tab, use your real staging email with a **wrong** PIN.
2. **Pass:** you're moved to Sign In with "If this email is new, check your inbox… If you already have an account, sign in with your PIN." You don't see "Account created".

**T5 · Sign out clears the page (#6)**
1. Sign in and let deals load, then sign out.
2. **Pass:** behind the sign-in screen, no deal cards or highlights remain. Check with DevTools → Elements: `#deals-grid` is empty.

**T6 · Unsubscribe still works (#3)**
1. In the last staging email (from v9.4 T7), click Unsubscribe.
2. **Pass:** the confirmation page shows your email. Click Confirm.
3. **Pass:** Notifications shows email alerts off. Turn them back on.

**T7 · Admin logs (#7, #9)**
You'll be asked for the admin secret again: v9.5 ends every older admin session once.

1. Go to Admin → Overview.
2. **Pass:** "Last run" matches the most recent scrape (your v9.4 Resend test).
3. **Pass:** the Inbound logs page loads, even if it's empty.

## 4. Production

Deploy with the existing secrets (`unset` them so `deploy.sh` reuses the live values). Every admin session ends once at deploy (fix #9); sign in to `/#admin` again with the **current** secret.

### Optional: rotating the exposed secrets (not done; Ben accepted the risk on 2026-10-12)

The Resend API key and both admin secrets were pasted into a chat on 2026-10-12, so rotate them now. **Don't rotate `UNSUB_SECRET`**: that would break the unsubscribe links in emails people already have.

1. **Resend:** create a new API key (Sending access, your domain) in the Resend dashboard. Keep the old one for now.
2. **Store it in SSM.** Use single quotes. `deploy.sh` only creates this parameter and never updates it, so `--overwrite` is required:

   ```bash
   aws ssm put-parameter --name /publix/resend-api-key --type SecureString --overwrite --value 're_NEW_KEY'
   ```

3. **Generate a new admin secret** and save it in your password manager:

   ```bash
   python -c "import secrets; print(secrets.token_urlsafe(24))"
   ```

4. **Production:** run the commit / deploy / push block from the chat, with `ADMIN_SECRET='…new…'` added to the deploy line. Every admin session made with the old secret ends (fix #9). Sign in to `/#admin` with the new secret.
5. **Staging:** redeploy staging the same way, with its own new `ADMIN_SECRET`, so it picks up the new Resend key from SSM.
6. **Check the new key works:** in production, Notifications → Send test email arrives. Then **revoke the old key** in Resend.

**After deploying, on cartwise.shopping:** repeat T4 and T5, and sign in to `/#admin` with the new secret.

## 5. Rollback

No data changes. Revert the files and redeploy. Sessions that v9.5 revoked stay revoked, which is the intended state.
