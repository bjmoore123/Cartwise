# CartWise v9.12 — Test Plan (admin metrics, email engagement, weekly admin report)

**Flow:** automated tests → staging deploy → manual checks → Ben approves → production deploy → one-time Resend setup.

## What changed

| Area | Change |
|---|---|
| Admin → Reports | Rewritten. Headline tiles, "Needs attention", 12-week trend, setup funnel, verification, activity, site health, email table, this week's deals, lists and stores. Sign-ups by month, users by location and popular items are kept. |
| Weekly admin email | Every Thursday 9 AM Eastern (10 AM in summer) to the admin address stored in SSM. Same numbers as the page. **Email me this report** on the page sends one now. |
| Email engagement | Delivered / opened / clicked / bounced / marked-as-spam per email type, from Resend's events. Needs the one-time Resend setup below. |
| New tracking | When each account verified and after how many reminders; totals from each weekly deal run; a weekly snapshot for trends. |
| Automatic actions | A spam complaint unsubscribes that account. A permanent bounce flags the account. |

**What starts empty and fills in over time**

| Item | Fills in |
|---|---|
| "vs last week" notes and the trend charts | After two Thursday reports (the first one saves the first snapshot) |
| This week's deals | After the next Wednesday deal run |
| "Verified within 24 hours / after reminder N" | Only for accounts that verify after this release |
| Delivered / opened / bounced | After the Resend setup, for emails sent from then on |

## 3. Manual checks on staging (hard-reload)

**T1 · Reports page.** `/#admin` → Reports. **Pass:** eight tiles; a green "Nothing needs attention" or an amber/red list; funnel, verification, activity, health, email, lists, location and popular items all show. Numbers are plausible against Admin → Users (total users, unverified count). The trend section shows a one-line note (no snapshots yet).

**T2 · Email me this report.** Click it. **Pass:** "Report sent to the admin address."; the email arrives with subject `[staging] Cartwise weekly report: …`, branded header, the same headline numbers as the page, no sideways scrolling on your phone.

**T3 · Scheduled run and snapshot.** Run the scheduled path by hand (staging's rule is disabled on purpose):

```bash
aws lambda invoke --function-name cartwise-staging-api --cli-binary-format raw-in-base64-out \
  --payload '{"source":"admin-weekly-report"}' out.json && cat out.json
```

**Pass:** `{"sent": true, "snapshot": "snap#<today>"}`; another email arrives; the Reports page now says "1 so far" in the trend note.

**T4 · New tracking.** Run `bash tools/test_emails.sh` (creates and verifies a test account, sends each email type), then refresh Reports. **Pass:** Email table lists Verify email, Verification reminder, PIN reset, PIN changed, Test email with Sent counts; "Verified within 24 hours" went up by one; PIN resets requested/completed went up.

**T5 · Not reachable without admin.** In a private window: `curl -s https://api-staging.cartwise.shopping/admin/metrics` → `{"error": "Unauthorized."}`. And the report can't be triggered over HTTP:

```bash
curl -s -X POST https://api-staging.cartwise.shopping/auth/login -H 'Content-Type: application/json' -d '{"source":"admin-weekly-report"}'
```

**Pass:** `Invalid email or PIN.` (this used to be a server error), and no report email arrives.

**T6 · Regression.** Sign in, deals, list, Admin → Users / Logging / Feedback, Forgot PIN.

## 4. Production deploy, then one-time Resend setup

After the production deploy (expect `EventBridge rule: cartwise-admin-report (ENABLED)`):

1. **Resend → Webhooks →** open the existing webhook that points to `…/inbound/email-list` → **edit events** → also tick `email.sent`, `email.delivered`, `email.delivery_delayed`, `email.bounced`, `email.complained`, `email.opened`, `email.clicked`. Save. Same URL, same signing secret: nothing to change in AWS.
2. **Resend → Domains →** your sending domain → turn on **Open tracking**.
3. Leave **Click tracking** off unless you want click rates: it rewrites every link in every email (including PIN-reset and verify links) to pass through Resend first.
4. Check: send yourself a test email from Notifications, open it, wait a minute, refresh Admin → Reports. **Pass:** the Email table shows Test email with Delivered 100% and Opened 100%.

If the Delivered column stays "–" after step 4: Admin → Logging → look for `inbound-sig-fail` (wrong secret) and tell me.

## 5. Rollback

Revert and redeploy. The metrics table and the EventBridge rule can stay (harmless). To stop the weekly email only: `aws events disable-rule --name cartwise-admin-report`. To stop event collection: untick the email events in the Resend webhook.
